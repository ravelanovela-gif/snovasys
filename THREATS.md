# TrustVault threat model

## Assets, boundaries, and assumptions

**Assets:** document bytes and metadata, grant state, account/session credentials, and audit records. **Trust boundary:** every HTTP request, including a valid login, is untrusted until the server authenticates it and checks the requested operation against current database state. File IDs and UI controls are not secrets or authorization. The application host, Python process, SQLite database, and `TRUSTVAULT_SECRET` are trusted; a fully compromised host is out of scope for this implementation.

The service assumes the deployment uses HTTPS, protects environment secrets, keeps `TRUSTVAULT_STORAGE` outside every static/public directory, and does not let an untrusted party modify the SQLite file. The sample accounts/passwords are for local demonstrations only.

## Attacks considered and controls

| Attack / threat | Control and verification |
| --- | --- |
| **IDOR: change a document UUID in a read, download, PATCH, or DELETE URL.** | `has_access` joins the current user to document ownership or a live grant for every operation. Unauthorized and nonexistent IDs both return 404. `tests/test_security.py` calls direct routes as an ungranted viewer and an administrator for read/download/edit/delete and checks owner isolation. |
| **Read a private file by guessing a storage URL or filesystem name.** | Blobs use random opaque names, are stored outside `static/`, and are not routed by path. The download endpoint obtains the blob key only after authorization. Download tests exercise the route; production must preserve the private-directory configuration. |
| **Treat a folder grant, viewer role, admin role, or UI button as authorization.** | There are no inherited folder permissions. Admin gets audit-only authority. The server filters listing queries by owner/current grant and independently protects each object route. Role-boundary and list-isolation tests cover this. |
| **Reuse an old shared link after access is withdrawn.** | No bearer links are issued. Revocation deletes the ACL row; every subsequent metadata/download request checks the database. The test downloads successfully, revokes, then verifies both routes return 404. A copy already delivered cannot be recalled. |
| **Escalate read to edit, delete, or share.** | Read/edit permissions are checked separately. Edit can change only metadata; deletion and grant administration require document ownership. An edit-grant test checks metadata succeeds but delete/share fail. |
| **Abuse admin access to enumerate documents or retrieve every file.** | Admin document listing is filtered to explicit grants; per-document access has no admin bypass. Tests verify the ungranted administrator cannot list/read/download. Audit endpoints are role-protected. |
| **Forge a filename to escape storage or inject a response header.** | Client filenames are basename-only, reject slash/backslash/NUL, are length-limited, and never become storage paths. Download `Content-Disposition` uses a sanitized ASCII basename. Opaque server-generated blob names are persisted separately. |
| **Upload a script, binary disguised as text, or fake PDF/image.** | Extension allowlist, 10 MiB size cap, strict base64, PDF/PNG/JPEG signatures, UTF-8/NUL checks, and ZIP-container validation for DOCX. No uploaded content is served as an inline browser page. Tests cover prohibited extension and signature mismatch. DOCX embedded content is not malware-scanned. |
| **Stored/reflected XSS in filename, category, email, or audit details.** | UI values are HTML-escaped before insertion; CSP disallows inline scripts and third-party connections. Filenames are sanitized on download. CSP is defense in depth, not a replacement for escaping. |
| **CSRF using a logged-in browser.** | SameSite=Strict, HttpOnly session cookie, and a separate session-bound `X-CSRF-Token` on each state-changing request. A bad-token test expects 403. Deploy same-origin only; do not add permissive CORS. |
| **Session theft, fixation, or stale session use.** | Random 256-bit bearer token, SHA-256 token hash at rest, HttpOnly/SameSite cookie, eight-hour expiry, logout invalidation, and Secure flag for HTTPS. No persistent download token. Production must enable Secure cookies and TLS. Password-change revocation and MFA are not implemented. |
| **Password guessing and account discovery.** | PBKDF2-HMAC-SHA256 (310,000 iterations), random salt, generic failed-login message, dummy hash verification for unknown accounts, and ten failures per remote address per 15 minutes. This basic in-process/database throttle is not a distributed abuse-control system; upstream rate limiting and MFA are needed for public deployment. |
| **SQL injection in filters, IDs, or identities.** | SQL values are parameterized; dynamic search column names are a closed server-side set. Never interpolate user-supplied SQL identifiers. Add dedicated regression coverage if query surfaces change. |
| **Audit update, deletion, forgery, or reordering.** | Every event is chained and HMAC-signed with an environment-held key. Database triggers reject ordinary update/delete; admin verifies full history. Denied document access and login refusal are recorded. Tests check denied downloads appear and the chain verifies. This is not independently immutable: a database operator can drop triggers or truncate a tail; someone with both DB write access and the HMAC key can forge entries. Production must export to a separate append-only/WORM service and periodically anchor signed chain heads externally. |
| **Audit contains sensitive data or becomes an exfiltration path.** | Audit details are limited to operational fields and no file bytes, passwords, or session tokens are recorded. Only admins can view the audit API. The admin view is bounded to the newest 500 records; full verification scans the whole chain. Email and IP addresses still count as sensitive operational data and require retention/access policy. |
| **Concurrent revocation/download or time-of-check/time-of-use race.** | Authorization is evaluated from the live ACL immediately before reading the private file. Requests already authorized and in flight at revocation may finish; an already downloaded copy cannot be recalled. Strict cross-process linearizability between byte transfer and revocation is not claimed. If required, coordinate revocation and streaming with a transactional storage gateway and define which operation wins. |
| **Deleted-document recovery or data remanence.** | Soft delete makes document routes inaccessible and removes grants; audit event remains. Blob bytes are retained and not exposed via the app. Retention, backup erasure, legal hold, and cryptographic deletion are not implemented and need an operator policy. |
| **Database/storage symlink, host compromise, or malicious administrator.** | Application-generated UUID storage keys and parent check reduce path mistakes. There is no defense against a fully compromised service account or host operator. Lock down file ownership, database/storage permissions, backups, patching, secret access, and deployment network. Encryption at rest is not included. |
| **Denial of service via huge requests, expensive auth, or audit growth.** | Request length and decoded upload are capped; login attempts are throttled; SQLite uses a busy timeout. Audit events are append-only and have no retention/rotation policy. Put a reverse-proxy request/body/concurrency limit in front, monitor disk, and move audit to a managed append-only sink before public production use. |
| **Supply-chain or runtime vulnerabilities.** | Application logic uses Python standard library; only optional Waitress is a runtime dependency. Pin/review/scan dependencies and keep Python patched. This repository has no automated dependency scanning or CI configured. |

## Known gaps and accepted risks

This challenge build is not a production security certification. It does not include MFA/SSO, external identity proofing, malware scanning, encrypted-at-rest key management, immutable external audit anchoring, account disable/admin UI, distributed rate limiting, audit retention controls, versioning, or secure erasure of soft-deleted blobs. Local demo credentials are public. A shared download already received cannot be revoked retroactively. The built-in `wsgiref` server is development-only; use a maintained WSGI server behind TLS for deployment. The environment used to author this project had no Python runtime, so the included tests still need to be run in a real Python environment before public exposure.

## Regression tests

`tests/test_security.py` maps the core IDOR, role, grant/revocation, metadata edit, owner isolation, file-validation, CSRF, search, and denied-access audit scenarios to direct HTTP-level WSGI tests. Add a test whenever a new route can return document metadata or bytes. A test suite is only meaningful if removing the corresponding server authorization check makes that test fail.
